# Security review before 1.0.0 — 2026-11-24

## Verdict

**Conditional approval of the plugin code; no unconditional approval of the full stack.**
No exploitable authentication bypass, open redirect, or XSS was found in the plugin.
However, the pinned test image contains an affected OIDC implementation and an outdated
Django security patch level. These findings must be checked against production and
fixed or demonstrably mitigated before approving the production stack.

Reviewed: commit `d920301` (plugin 0.3.0), including the tests and development port
hardening added during this review. The operator reports trouble-free production use
with NetBox 4.7; this does not replace checking production dependencies.
No production access, deployment, version bump, or tag was performed.

## Findings

### S1 — OIDC nonce not bound to the browser session (moderate, release prerequisite open)

The test image contains `social-auth-core 5.2.0`. Its actual installed source shows
that `OpenIdConnectAuth.get_nonce()` retrieves the nonce from shared Association storage
by server URL and handle. `validate_claims()` does not verify a binding to the browser
session that initiated authentication. `DEFAULT_USE_PKCE` is `False`, and the
development configuration does not enable PKCE.

This matches [GHSA-h2r5-x5m7-3935 / CVE-2026-115910](https://github.com/python-social-auth/social-core/security/advisories/GHSA-h2r5-x5m7-3935):
an attacker holding a stolen, unused authorization code can redeem it with their own
valid state. The advisory lists 6.2.0 as patched. Local verification covered the
installed version and source, not a complete attack against a real IdP.

**Image action:** use a patched social-auth version compatible with NetBox. As a targeted
mitigation, enable `SOCIAL_AUTH_OIDC_USE_PKCE = True` with S256 and verify that authentik
enforces the verifier during token exchange. The added regression test verifies the
challenge and session verifier at login start; it does not replace end-to-end IdP
verification. The production version and effective PKCE setting were not collected.
The plugin does not silently override dependencies.

### S2 — Outdated Django security patch level in the test image (open, image responsibility)

The installed version is Django `6.1.2`. The [2026-11-03 security release](https://www.djangoproject.com/weblog/2026/nov/03/security-releases/)
fixes issues in 6.1.3 including multipart memory exhaustion (CVE-2026-108147) and cache
variation handling. The bridge already sets `no-store, private`; no cache leak of
this plugin page was demonstrated. GIS- and admin-specific advisories do not establish
an attack path through this plugin.

**Action:** check the production image's Django version, use a compatible security
patch level, and rerun the tests. This is not a blanket exploit claim or a full CVE
scan of every image package.

### S3 — Development services published on all interfaces (low, fixed)

`dev/docker-compose.yml` published NetBox and the dummy IdP on all interfaces through
`8000:8080` and `9000:9000`. The environment deliberately uses known test credentials
and a known Django secret key. Reachable ports therefore unnecessarily exposed the
test environment to the local network.

Both bindings now explicitly use `127.0.0.1`. PostgreSQL and Redis have no published
host ports. Test values remain development-only.

## Security boundaries checked

- Password blocking resolves the actual Django view using `path_info` and optional
  `request.urlconf`, independently of query parameters and authentication status.
  Invalid boolean configuration fails closed. An invalid redirect backend does not
  disable the password block.
- Standard NetBox routes were checked against [login and SSO start](https://github.com/netbox-community/netbox/blob/v4.7.3/netbox/account/views.py),
  [token provisioning](https://github.com/netbox-community/netbox/blob/v4.7.3/netbox/users/api/views.py),
  and [URL routing](https://github.com/netbox-community/netbox/blob/v4.7.3/netbox/netbox/urls.py).
  Additional admin, Basic Auth, or plugin login routes are outside the block's scope.
- Redirects use Django host/scheme validation for query and session values, reject HTTPS
  downgrades, and validate the last repeated parameter. `LOGIN_REDIRECT_URL` remains
  trusted operator configuration. social-core also validates direct SSO starts unless
  `SANITIZE_REDIRECTS` is disabled.
- Automatic and manual SSO starts use POST with a CSRF token. The plugin adds no CSRF
  exemption. Tests were added for foreign origins despite a valid token and GET on
  both SSO start routes.
- Query values are escaped in the template; the script has no dynamic HTML sinks.
  `BANNER_LOGIN|safe` preserves NetBox's intentionally trusted operator configuration.
  The IdP URL comes from the server-side authentication backend, not directly from query data.
- The bridge sets `no-store, private` and `X-Frame-Options: DENY`.
  Recovery redirects and blocked-login responses are also non-cacheable.
- No production secrets were found in current tracked files; development values are
  identifiable. No complete historical secret scan was performed.
- Test-image dependencies: Django 6.1.2, DRF 3.18.0, social-auth-app-django 6.1.0,
  social-auth-core 5.2.0. The plugin relies on NetBox's dependencies rather than
  declaring its own runtime pins.

The [OpenID session restoration advisory](https://github.com/python-social-auth/social-core/security/advisories/GHSA-wmvf-3hv6-r972)
explicitly concerns OpenID, not OIDC. The [MySQL collation finding](https://github.com/python-social-auth/social-app-django/security/advisories/GHSA-mmhh-p37m-v88f)
does not establish an attack path in this PostgreSQL test stack.

## Validation

Against the NetBox 4.7.3 image pinned in `dev/docker-compose.yml`
(`sha256:22cf3c61fc367fb74a5cf6de018e9d7e10a7da8d09a695eab30740793040de08`):

- `manage.py test netbox_sso_redirect --keepdb -v 1`: 89 discovered, 85 passed,
  four BASE_PATH tests skipped as expected; exit 0.
- With `BASE_PATH=netbox/`: `manage.py test netbox_sso_redirect.tests.test_base_path --keepdb -v 1`:
  all four passed; exit 0.
- Eight new tests cover adversarial redirect targets, foreign CSRF origins, GET start
  rejection, PKCE S256 session binding, method overrides, other HTTP methods, session
  value types, and HTTPS downgrades. Existing tests also cover XSS escaping, actual
  password/token blocking, misconfiguration, and SSO cancellation.
- `git diff --check`, Python compilation, `node --check`, and
  `docker compose ... config --quiet` passed.

Test warnings concern the missing API v2 token pepper and NetBox's deprecation of
`LOGIN_REQUIRED`. Existing token tests use API v1 tokens.
No browser/IdP end-to-end test or complete image vulnerability scan was performed.

## Conditions for 1.0.0

1. Resolve S1 in the actual production image or demonstrate effective PKCE.
2. Close S2 with a compatible image security patch level.
3. Run regression tests against that exact release image and briefly verify the
   authentik login, cancellation, retry, and logout flow.

Proxy trust, TLS, cookie settings, authentik policies, and the custom role pipeline
were not audited live. The documented limits of `local_login` and the NetBox 4.7
compatibility ceiling remain unchanged.
